# LootRadar

Українська геймерська платформа-агрегатор знижок, історичних мінімумів та роздач у Steam (статичний фронтенд-проєкт).

## Стек технологій

- **HTML5** — семантична розмітка з підтримкою доступності (`a11y`, `aria-*`, `role="alert"`, `role="dialog"`)
- **Tailwind CSS (CDN)** + власні дизайн-токени в `styles.css`
- **Vanilla JavaScript** — клієнтська логіка, wishlist (`localStorage`) та валідація форми зворотного зв'язку

## Структура проєкту

```text
LootRadar/
├── index.html               # Головний лендинг платформи та форма зворотного зв'язку (#feedback)
├── account.html             # Сторінка кабінету користувача (демо Steam OpenID 2.0 та wishlist)
├── styles.css               # CSS-токени та додаткові стилі
├── assets/
│   ├── icons/               # SVG-іконки інтерфейсу
│   ├── images/              # Зображення ігор, логотип та фон банера
│   ├── js/
│   │   └── validation.js    # Модульна клієнтська валідація форми зворотного зв'язку
│   └── video/               # Відеоматеріали
└── README.md
```

## Форма зворотного зв'язку та клієнтська валідація

Секція `#feedback` у `index.html` та скрипт `assets/js/validation.js` реалізують адаптивну форму з перевіркою даних на стороні клієнта:

- **Ім'я або нікнейм (`#username`)** — обов'язкове, 2–50 символів (літери, цифри, `_`, пробіли, дефіси, апострофи).
- **Електронна пошта (`#email`)** — обов'язкова, перевірка формату через RegEx (`REGEX_EMAIL`).
- **Номер телефону (`#phone`)** — обов'язковий, формат `+380XXXXXXXXX` (`REGEX_PHONE`) із безпечною нормалізацією пробілів/дужок/дефісів та формату `0XXXXXXXXX`.
- **Steam ID / Профіль (`#steamProfile`)** — необов'язкове поле, від 3 до 64 символів без пробілів (`REGEX_STEAM`).
- **Тема звернення (`#topic`)** — вибір категорії.
- **Повідомлення (`#message`)** — обов'язкове, мінімум 10 символів із живим лічильником (`#currentLength`).
- **Згода (`#agreement`)** — обов'язковий чекбокс.
- **UI-стани та доступність** — динамічна перевірка на `blur`, `input`, `change` і `submit`, візуальні стани Normal / Focus / Error / Success, а також доступне модальне вікно `#successModal` (імітація успішного надсилання без передачі даних на сервер) із закриттям по `Escape` / кліку на оверлей і утриманням фокусу на `Tab` / `Shift+Tab`.
